# Document delivery and return work in progress

D is under independent PR review. Candidate packages have been installed and
upgraded in an exterior disposable profile; configured PDF delivery, cancellation
and same-profile restart have representative actual evidence. Microsoft Word
round trips and final UI acceptance are still open. The complete A–E objective
has not been achieved.

The current Word projection consumes the primary ProseMirror document and actual
step/mirror history. Text and paragraph-mark revisions share one SDK export path;
the former fixed-paragraph exporter has been removed. Selected comparison B and
delivered working body E are recorded separately. Word rejection is relative to B;
return comparison uses E as the common ancestor of the returned file and current P.
No delivered change is proposed again merely because it differs from B.

Immutable delivery receipts retain the actual output, E/B, variant, native
paragraph evidence and applicable Chinese versions. Download retries reuse that
receipt. Clean, tracked and bilingual copies use the same source package. The
bilingual copy requires complete current paragraph groups; it cannot present stale
or partial Chinese as a complete translation. Original uploads/resources remain
available separately from metadata-clean derived exports.

Native supported text comments enter the existing feedback owner while retaining
their original bodies in the source package. Reasons derive from committed steps
and actual candidate/feedback relationships. Ambiguous/stale locations are explicit;
they are not silently moved to a convenient occurrence. Unchanged supported native
comment ranges retain their exact delivered text scope. An overlapping accepted
change requires an actual linked feedback/reason before moving the comment to the
changed paragraph, with an explicit warning and retained original quote. Newly
generated reasons use paragraph scope. Revisions in preserved headers, footers,
notes and other external stories must be resolved in Word before intake; a
primary-body choice does not pretend to resolve those stories.

Returned files retain their raw bytes and explicit existing-revision projection.
Marker mismatch prevents proposals. Missing or changed paragraph identifiers require
human alignment. Granular E-to-return text changes map strictly into P, retaining
unrelated local work and exposing overlap conflicts. They become ordinary pending
candidates through the existing acceptance owner. A bounded comparison now checks
that all optimal content-word/punctuation matchings use the same source pairs.
Repeated wording with multiple pairings is explicit and is not used to locate a
text candidate or an old-source comment. Whitespace is retained in complete gaps
between confirmed content anchors, including known paragraph boundaries. The
comparison bounds allocation and elapsed work; an unCompared paragraph does not
prevent the other paragraphs from being checked. Full native properties are compared
at actual matched spans, including format removal/reassignment and equivalent run
segmentation. Formatting, moved paragraphs and
unmatched structural changes remain explicit review items; the current text-only
return proposal does not apply them. Supported returned comment text can be copied
to ordinary feedback after its exact current source range is confirmed. New returned
wording must be accepted before comments on it can be copied. This text-only action
retains return/comment provenance and does not copy rich comment bodies or accept
the returned manuscript automatically. The original returned DOCX remains available.

Markdown uses a separately managed process with the unmodified public
`pandoc-wasm@1.1.0` runtime dependency, whose included program reports Pandoc 3.10.
DSH's package installer is responsible for that public dependency. No manual
Pandoc installation or development toolchain is intended. The process receives only
explicitly supplied text/resources. Pandoc parses the source, its temporary AST
rewrites supplied image/bibliography targets, and the SDK normalizes the resulting
Word source. UTF-8, resources, raw HTML/TeX and read-only objects have explicit
boundaries. Common text, native tables/equations/notes, Unicode nested images and
supplied bibliography have direct checks; this is not arbitrary-format fidelity.
Version-specific GPL/copyright texts, the unmodified wrapper license and correct
source/build pointers are included in the package. The alpha.1 dependency was
actually installed from the public registry in an exterior empty profile with
isolated pnpm store/config/cache/auth; its normal lockfile/integrity and installed
runtime resolution were checked. Offline first installation failed clearly and
restored the manifest. Two external dependencies were downloaded; the local plugin
tarball alone was reused from that same offline attempt. This does not establish
offline first-install support. The plugin's own license has not
been changed; an external-process boundary is not a legal compliance conclusion.

PDF uses DSH's existing OfficeToPdf authorization/admission/read/converter lifecycle.
The immutable export is generated only after shared admission. The caller cleans its
owned result, including Info/XMP and optional generated annotation title/date fields;
comment content, references and Widget field names retain their functional roles.
The shared cached PDF/source is not rewritten.

Direct service fixtures produced and rendered three one-page PDFs with explicitly
configured system font roots, including CJK, tables/math/notes, native tracked
markup and actual PDF reason annotations. Missing-font declarations are retained.
The default font discovery also reproduced a blocked font-metadata worker, caller
timeout and incomplete graceful disposal. It is not fixed or accepted by the explicit
configuration probe. The plugin does not silently replace shared Host font settings
or create another converter. The candidate now offers an explicit font-only settings
projection and user-chosen application through DSH's existing ConfigEditor. The form
discloses shared-preview impact and the fact that saving may remove notes inside the
target Office configuration block. Unchanged raw fields, expressions and settings
outside that block stay with their existing owner. Closing the draft form does not
write; applying an unchanged choice does not reload. Paper actions join normal
shutdown, while the global editor owns the admitted configuration action across a
dependent Paper reload, avoiding a self-wait. Actual installed reload, PDF delivery,
cancellation and same-profile graceful exit/restart have representative alpha.2
evidence: the cancelled request did not create a receipt, a new one-page bilingual
reason PDF retained its missing-font warning, and the saved PDF was byte-identical
after restart. Its optional Info/XMP and generated annotation properties were
checked; the actual page was opened. This evidence covers the configured path and
does not repair the default font-discovery failure.

The alpha.2 source passed the complete 94 owner/SDK checks. The subsequent comment
provenance correction and font failure-state presentation passed the 11 affected
return/font checks and type checking; unaffected evidence is retained. Direct
SDK accept/reject projections cover empty-to-multiple paragraphs, split/merge,
inverse history, nonzero B, complete native formats, comments and source evidence.
Managed-process intake covers retained Markdown/resources and joined cancellation.
These checks are distinct from actual Word, installed Host/model and user acceptance.
