# 产品设计基线

状态：用户已要求固化并实施的产品目标。本文定义目标行为，不宣称已有代码或验收结果。

## 1. 问题与定位

科研写作中的关键成本发生在多轮修订：英文阅读费力、中文回译覆盖已确认英文、Agent
重写过大范围、用户找不到改动、导师返稿与后续版本无法比较。单次生成质量不能替代
对修订过程的理解、控制和交付。

Paper Workbench 是 DSH 的论文协作插件。复用通用 Agent 的调查、检索、代码和工具，
补齐文档结构、双语视图、批注、候选操作、独立审读和 Word 交接。课程允许自选科研
写作扩展；具体报告格式和评分细则尚未提供，不自行发明额外课程硬性要求。

## 2. 用户与核心任务

- 写作者：从研究材料开始写作，或上传已有论文；以中文理解和提出反馈，核对英文。
- 合作者/导师：可继续使用 Word；直接修订和批注后返回文件，理解上一轮具体变化。
- 普通 DSH 使用者：安装发布包即可启用，不 fork DSH、不编译产品源码、不手改宿主配置。

用户始终使用 DSH 原有通用 Agent 及原生对话 UI。论文侧栏对安装插件的环境中所有
普通任务可用：已有、新建、恢复、非论文任务都能直接打开。产品不提供独立“创建论文
Agent”入口，不要求切换角色、preset、profile 或另开论文专用会话。只有明确关联论文
或发起相关操作后才加载论文上下文。文档唯一输入入口是原生主对话：附件、@文件/本地
路径、链接或从头写作要求，由普通 Agent 调查并调用后台导入/关联。侧栏空态只说明
这一入口，不提供上传、稿件名称、主语言、研究目标或关联论文配置表单，也不保留高级入口。

界面操作不要求输入块 ID、修订 ID 或内部引用。正文链接、聊天引用和批注可互相定位。

## 3. 目标流程

1. 在原生主对话上传文件、提供文件/链接或从头写作要求；普通 Agent 调用正式后台，自动打开论文标签页。
2. 识别正文结构、引用、图表、已有批注和修订，说明支持域与待核对项目。
3. 根据用户明确指令选择主语言，缺省英文；导师交付基准由真实标记核对，歧义在主对话澄清。未接收的 Word 修订由用户明确选择处理。
4. 生成绑定到准确正文修订的逐段中英对照；在窄栏上下排列，宽栏可双栏。
5. 用户选择正文或译文，在对应位置添加短批注、回复、解决/重新打开；自动保存，积累后一键提交本轮批注。聊天仍可补充整篇方向。
6. Agent 理解整批反馈、调查证据、处理矛盾和联动，提交必要范围的候选操作。
7. 程序展示真实差异与反馈关联；本轮候选完成后由系统自动启动新会话独立审读，问题只读定位到具体段落/候选。
8. 用户逐处或按必要依赖组接受/拒绝、补充反馈，也可接受全部可处理修改。
9. 保留历史、恢复中断；导出不同用途的文档，接收返稿后继续同一论文。

从头写作产生的初稿进入同一文档生命周期；缺实验、文献或实现事实时先调查或明确待补，
不能编造结果。用户不必先有完整研究问题才能讨论，初步想法也可在普通聊天中展开。

## 4. 双语语义

- 一份主语言正文拥有权威，译文关联其准确修订；主语言可由用户显式选择。
- “只纠正译文”不改正文；“用中文表达内容修改”形成英文和相应中文的候选修改。
- 不经中文回译重建整篇英文。用户直接改英文后仅更新受影响译文。
- 未完成同步的译文明确显示过期或更新中，不能正常展示为当前版本。
- 保持行动主体、否定、条件、数字、术语、引用和结论强度一致。
- 支持段落拆分/合并/移动的关联；中文选区不必与英文字符范围一一对应，定位不准时
  显示实际可确认的句群或段落范围，不假装短语精确对齐。

## 5. 反馈、修改和接收

- 局部批注和全文方向共同构成本轮输入。批注来源、选区、意图及状态可定位。
- Agent 提交 replace/insert/delete 及必要结构操作，程序保留原片段并计算真实差异。
- 每个修改关联原稿位置、正文修订、反馈、理由、必要证据、依赖及审读状态。
- 最小必要范围不是最少字符。定义改变造成的前后联动明确解释并成组处理。
- 未接受建议不覆盖当前正文。接受/拒绝同步相关双语状态，历史仍可查看和撤销。
- “已提出修改”“独立审读完成”“用户已接收”“反馈问题已解决”不是同一个结论。
- 存在冲突或依赖时，全部接受按钮说明将处理的范围与剩余项，不能静默部分处理并
  冒称全部完成。跨组依赖须呈现或合并为实际可独立决定的组。
- 用户工作期间继续编辑时，仅重新定位/拒绝实际失效或冲突范围；无关编辑不让全部
  候选过期。上下文改变引起的语义影响仍需审读。

## 6. 独立审读

每批写作/修改完成后，由正式 DSH 轮次生命周期自动启动新的自包含会话，覆盖首稿、
主聊天修订和提交的侧栏反馈。用户不点审读启动按钮，不填写目标/证据或另选审读模型；
不能仅靠 Skill 提醒写作者调用。材料包括实际用户目标、准确基准与候选、反馈、
证据及上下文，不提供写作者的推理作为审查结论。使用相同模型也只能保证上下文隔离。

审查反馈意图、无关改写、导师已确认内容、上下文一致性、主张证据、双语语义及正文
中的过程残留。让读者复述问题、机制协作和反馈用途，发现概念或职责理解偏差。

审读意见不自动覆盖正文，也不替用户接受。结果绑定候选修订；接受部分修改产生的新
组合影响了原结论时，补查受影响部分，复用其余适用证据。不无限自动互改或扩大预算。
审读失败或未完成准确呈现，不能假报通过。
同一完整组合幂等，变化后才补相应新审读；无相关论文候选的普通问答和读者自己的轮次
不触发。纯翻译任务不另起科学审读，写作候选的成对译文始终纳入；译文变化仍使旧双语
适用性失效。不逐次 propose 过早审读，也不无限自动重试、互改或接受。

## 7. 界面行为

- 使用原生 DSH 对话区、消息流、工具呈现和主输入框，主 Agent 核心架构不改；在已有
  右侧栏扩展可展开的论文工作台。示意图的对话只是背景，不是要求实现第二套聊天 UI。
- 所有普通任务都可打开侧栏；批注清单、补充反馈及修订接收控件放在插件侧栏内。
  每个会话的视图状态独立；复用同一论文需显式关联并读取同一文档权威，不复制正文。
- 提供阅读、修订和历史/反馈所需视图，避免为内部状态增加仪表盘。
- 展示精确增删、修改理由、关联批注与独立意见；正文和修改说明有清楚边界。
- 选择正文/译文添加批注，选区高亮、定位和短批注卡与正文同屏；自动保存，回复及解决状态由同一反馈 owner 保存。积累后一次提交，支持聊天方向关联。
- 接受后可继续比较本轮开始、导师返稿或已保存版本；不会仅剩干净全文。
- 自动保存、重启恢复、取消、键盘操作、可访问标签和窄屏可用属于实际交互范围。
- 用户能理解定位冲突、过期译文、未支持对象、审读未完成和导出失败并采取下一步。

## 8. 格式与交付

DOCX 与 Markdown 是首要完整支持入口。LaTeX、文本 PDF、扫描 PDF/图片按经过验证的
支持域逐步接入；任意格式无损、任意复杂宏/对象可编辑不属于承诺。

保留原文件，转换完整性说明列出可编辑、原样保留和需人工核对内容。未支持对象不
静默丢弃；不把重建稿称为保真原稿。复杂字段/公式/跨段修订须用实际样例确定边界。

输出英文干净 DOCX、原生修订 DOCX、双语工作 DOCX 和 PDF。修订稿相对用户选定的
基准生成真正的 Word 修订与可选理由批注；红字/删除线不能冒充可接受拒绝的修订。
工作台接收与导师审阅是两层关系。返稿按上次导出基准、外部返稿和当前正文进行比较，
锚点歧义由用户核对。第三方软件改变标识不应导致静默错贴。

## 9. 写作技能

按需加载四类技能：研究论证与机制表达、基于反馈的局部修订、双语科研写作、独立审读。
项目术语、实现事实、实验和格式要求保存在论文材料中，不写进跨论文通用技能。

研究论证保留九层判断：核心转变；章/节/段职责；读者可建立的概念体系；因果机制；
决策主体和执行职责；通用机制/条件案例/实现细节；空白/贡献/证据对应；篇幅价值；
修订和审读发现理解偏差。少量前后实例解释问题、修正和保留内容。

研究边界和证据限制有实际用途，保留在适当位置；删除面向提示词或写作过程的自我说明，
不机械禁用 Agent/模型等研究对象术语。不要求输出隐藏推理，只需简短、可检查的修改理由。

## 10. 分发和完成边界

最终用户从公开发布包通过 DSH 正式入口安装，得到已构建 Host/Client、所需资源和
明确依赖。无需编译源码、开发者绝对路径、私人 npm 权限或克隆上游源码。

宣称支持的平台、DSH 版本和文档特性须有实际证据；未测的组合标未验证。升级/卸载
保留论文资产与历史，并按用户操作退出插件资源。具体出口见验收标准。
