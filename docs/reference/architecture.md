# 技术说明

## DSH 接入

插件通过 `cordis.patch.yml` 注册 Host 服务，并由 `src/host.ts` 接入 DSH 的工具、会话事件、存储、文件和子会话能力。`src/client.tsx` 使用右侧栏扩展点提供工作台，`src/remote.ts` 定义界面与 Host 之间的请求通道。主对话保留 DSH 通用智能体的工具和交互方式。

界面操作与智能体工具调用同一文档服务。文档导入、批注、候选、用户决定和导出共用状态更新路径，正文只有一个可编辑来源。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `records.ts`、`contracts.ts` | 持久记录、工具请求和结构化审读输出 |
| `operations.ts` | ProseMirror 文档、选区验证、事务映射、编辑与差异 |
| `model.ts` | 批注、候选、翻译、依赖、决定和历史更新 |
| `reading.ts` | 冻结审读材料、生成读取提示、校验输出位置及审读适用性 |
| `host.ts` | 组合上述能力，协调 DSH 生命周期与持久化 |
| `client.tsx` | 文字选择、批注、双语候选、审读及交付操作 |
| `word.ts`、`delivery.ts`、`returns.ts` | Word 投影、交付记录和返稿三方比较 |
| `markdown.mjs`、`document-engine/` | Pandoc Markdown 转换及 Open XML SDK DOCX 处理 |
| `pdf.ts`、`office-fonts.ts` | PDF 内容投影与 DSH 共享字体配置接入 |

## 文档、选区与候选

正文采用 ProseMirror 结构化文档。内容块拥有持久身份，选区保存文档、源修订、内容块、范围和准确引文。执行操作前，程序校验块、范围及引文；旧选区通过历史事务映射到当前正文。目标自身发生冲突时，操作返回诊断，供智能体重新读取位置。

智能体提交候选操作，支持段内替换、段落拆分、相邻段落合并和空草稿填充。候选保留源选区、反馈、理由和依赖。程序根据实际结构变化计算差异，候选预览不直接改写已接受正文。

继续修订待定候选时，新候选通过 `revises` 指向原组，仍基于已接受正文提交完整操作。原候选和审读材料保持原值，后继关系控制当前可决定的候选集合。界面分别展示已接受正文到候选的差异，以及前一候选组合到当前组合的差异。

用户接受时，程序重新核验选区和依赖，在同一更新中处理正文、译文关联、决定和历史。拒绝留下决定记录，撤销形成后续状态变化。持久化成功后，结果才对界面和工具调用方可见。

## 双语关联

译文记录绑定主语言范围及修订，允许多个源范围对应一个译文组。正文变化后，受影响译文标为过期；翻译任务完成时再次核验源状态，避免迟到结果覆盖新内容。

译文表达纠正使用翻译刷新路径，保持主语言正文。研究内容修改通过正文候选及其配对译文完成。正文、译文和候选的版本关系也用于判断审读意见是否仍适用。

## 独立审读

Host 监听 DSH 的 `agent/turn-stopping` 事件，在该轮候选汇集后准备审读。同一组合复用已有任务，普通问答和读者自己的轮次跳过该流程。

审读材料冻结基准正文、候选投影、用户方向、已提交反馈及配对译文。用户方向依据消息来源收集，包含直接要求、澄清答复及对应版本的任务目标。运行环境注入文本不作为用户方向；已送达反馈按所属稿件保留，独立于写作者是否引用这些反馈。

读者使用新建的 `spawn` 会话，通过只读工具取得材料。输出区分候选问题、原稿已有问题和可选建议，并提供位置、引文、影响及依据。程序校验发现能否定位到冻结材料，再保存结果。主会话可据此继续修订，用户决定另行保存。

每项审读管理自身的激活资源与终态。取消停止对应任务；宿主恢复时将未完成任务标为中断。显式重试沿用原冻结反馈范围，失败记录与原候选继续保留。

## 存储与格式

Host 使用 DSH `storageDomain` 保存文档聚合和历史关系。原始文件及交付文件作为不可变材料保存，工具和界面读取同一份状态。

DOCX 引擎基于 Open XML SDK，将可编辑文字投影为结构化段落，保留复杂对象的原始结构。`word.ts` 根据基准与当前正文生成 Word 修订、批注和修改理由；交付记录保存所用基准及输出，返稿比较使用交付稿、返稿和当前正文。

Markdown 通过 Pandoc WASM 与显式提供的资源转换。PDF 使用插件生成的内容投影及 DSH 共享 Office 服务。文件格式和操作范围见[安装与使用](../install.md)。
