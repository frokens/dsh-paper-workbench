# 架构设计

状态：目标架构；各扩展 API 已有静态源码依据，产品实现尚待纵向验证。合理的等价技术
调整须说明证据和影响；改变产品行为、范围或必选验收须先取得用户裁决。

## 1. 分工与组合根

采用一个可分发 DSH bundle，包含必要的 Host 服务、Client 标签页、原生论文工具和
按需写作 Skills。Client 标签页注册在普通会话共同可见的正式扩展层，不能仅放进一个
论文 preset 或论文会话创建流程。原生聊天 UI 与主 Agent 核心架构保持不变，不新增
专用 Agent 创建入口、第二个主输入框或主会话运行时。独立审读只复用按需子会话机制。
起步使用一个清楚的包边界，不预先建立多包平台。源目录按当前职责
划分，实际代码结构由最小纵向切片验证；不为每个 helper 拆模块。

| 部分 | 权威职责 | 当前消费者 |
| --- | --- | --- |
| Host 文档服务 | 读取、反馈、候选修改、用户接收、导出请求和修订关系 | UI、论文工具、审读流程 |
| 文档模型与操作 | 论文结构、选区映射、操作应用和真实差异 | Host、编辑器、格式适配器 |
| Client 工作台 | 阅读、选区、批注、差异和决定的交互呈现 | DSH 右侧栏及用户 |
| 格式适配器 | 来源格式到结构的投影、来源映射、支持域和导出 | 导入/导出应用操作 |
| 审读协调 | 正式写作轮次完成点、准确候选材料、新会话、结果绑定、取消和资源退出 | 主聊天/反馈写作、只读结果与失败重试 UI |
| Skills | 写作和审读原则、按需资料组织 | DSH 通用 Agent 及审读会话 |

UI 和工具只做入口转换，调用同一应用操作。DSH 管 Agent、权限、模型、通用工具及
宿主生命周期；插件管论文语义，不另建 Agent 运行时、聊天系统、通用权限或调度平台。
文档与导师返稿只从原生主对话的附件、文件引用、路径或链接进入；普通 Agent 沿正式
调查/下载/文件服务调用同一导入 owner。侧栏负责批注和用户决定，不保留稿件输入表单。

## 2. 文档表示

以 ProseMirror 的结构化模型和事务作为编辑底座，按当前支持域定义标题、段落、列表、
表格、图片/题注、公式、引用、脚注等节点。实际版本及依赖写入锁文件后再核支持域。

正文是唯一可编辑权威。翻译、批注、候选和来源映射是关联记录，不是另一篇可独立
演化的正文。Pandoc AST、DOCX 和 HTML 均为输入/输出投影，不长期维护多个可编辑真相。

内容块使用持久身份；拆分/合并/移动记录实际关系，不能靠数组下标定位。文本样式、
引用和公式不能被简化为字符串后无提示丢失。暂不支持编辑的对象保留来源并明确边界。

## 3. 选区、候选与差异

读取正文返回程序可解析的选区引用，绑定文档、内容块、结构范围和准确修订。Agent
无需手工计算全局偏移或回传后端已知的哈希。选区包含对实际片段的校验，避免重复文字
或过期位置被错误替换；存在歧义时返回可行动诊断而非猜测。

候选操作为 replace/insert/delete 及当前确需的结构操作。服务器从准确基准取得原片段，
保存新片段和关联反馈，基于结构/文本计算差异；模型的修改说明只解释目的。

一个候选组对应用户可独立决定的语义单元。必要的双语状态与跨位置依赖一起处理；
全局换术语等任务可以有多个位置，但须准确说明影响范围。不能对整篇自由重写后只显示
模型声称修改的几处，也不把最小必要修改误设为任意字数上限。

现有事务映射优先用于重定位。无关编辑后的有效选区可以复用；与删除、结构变化或
重叠编辑冲突的建议标为需重定位/重做。模型读过的上下文发生变化时另判断语义影响。

## 4. 修订与用户决定

文档修订是实际内容状态的身份，用于来源、候选、比较与并发；不得变成任意资格标签。
同一操作重复提交应复用已有请求身份或准确操作状态，避免接收重放造成重复插入。

接收操作在一次持久更新中核目标仍有效，应用必要操作，更新正文修订、翻译关联、
用户决定和依赖状态。失败不暴露半接收正文。拒绝保留基准与理由，撤销是新决定，
不伪造抹除历史。已接收修改仍可相对导师基准或本轮起点显示。

“全部接受”先计算可执行范围和未解决冲突；用户能看清处理范围。相互依赖的修改不能
被拆成无法成立的半组。部分接收后的实际组合需判断原审读证据是否仍适用。

## 5. 翻译关系

翻译记录关联主语言内容块及准确修订，保存译文和句群对应。更新正文使受影响译文
过期；生成完成后核源仍是该修订再发布，迟到结果不能覆盖新译文。

译文措辞纠正与正文内容修改使用不同的明确意图。后者产生主语言候选与相应译文，
不将中文草稿自动反向作为全篇英文来源。句群对应可多对多，不能强求字符单调对齐。

## 6. 审读与上下文

任意普通主会话保留原生能力。没有论文关联也能打开侧栏，空态引导回原生主对话输入
文档。新建、已有、恢复和非论文会话使用相同入口与注册，不按任务类型过滤。
每个会话保存自己的视图/选择；显式关联同一论文时读取同一文档服务权威并处理实际并发。

插件仅在需要时增加当前论文、提纲、术语、待处理反馈及
准确读取入口；全文、大量文献和历次日志不重复塞入 system prompt。

上下文压缩后从持久状态恢复文档和当前工作，不靠聊天摘要重建权威正文。材料读取
沿当前任务选择正文、相邻段、关联定义、证据及必要全文；局部编辑不意味着忽略上下文。

候选由实际写作 session/turn 标记，在正式 `agent/turn-stopping` 完成点聚合后自动通过
DSH 的 fresh spawn 创建审读会话，使用自包含材料和所需工具/提示词
scope，不能通过 fork 继承写作者完整对话后宣称独立。审读需要读取和调查能力，但不
代用户提交接受。主会话的通用工具和权限不因此被全局收窄。
首稿、主聊天修订和侧栏批注提交共享此路径；同一组合不重复启动，实际变化后才补聚焦
审读。普通问答、纯翻译任务和读者轮次不启动科学审读，不逐次 propose 或依赖 Skill
提醒启动；用户不填写审读参数。失败重试仍使用原有 Reading/子会话生命周期。

审读输出定位、问题、影响、依据及建议，不输出隐藏推理。结果关联准确候选。修改后
仅在实际影响下复查，防止互相自动重写形成无界循环。保留中断/错误，不当成质量通过。

## 7. 存储、资产及恢复

优先使用 DSH storageDomain，而非为论文新建另一套数据库和 Repository。其当前
合同提供串行持久更新，但无跨表事务、跨进程变更可见性，不可假设它们存在。

起步将需要共同提交的论文状态作为一个聚合更新；较大不可变原件/资产先安全写入再
发布引用。失败留下的未引用资产不成为已发表正文，也不为此开发通用资产平台。
实现阶段以实际文档体量验证更新成本，发现具体瓶颈后再提有界存储调整。

保留恢复当前论文与比较历史所需的信息，避免每个 UI 事件保存全篇新副本。持久化成功
后才通知 Client；重启读取同一状态，旧请求结果必须核其来源修订。取消释放具体请求
资源，不杀其他任务，不遗失已保存批注。

插件不对拥有同等文件系统权限的宿主承诺强安全隔离。通过正式文档 API 维护接收约定；
外部编辑作为新的输入或候选，不能无提示覆盖当前权威。沿 DSH 既有权限与文件合同
执行解析和导出，处理不可信文件时使用库的安全选项及必要的有界资源控制。

## 8. 格式适配

DOCX 需要保留原包、关系和支持对象的来源映射；普通转换与修订语义分开评估。
Pandoc 可承担合适的通用结构转换和干净稿路径。Word 原生修订适配器优先评估成熟
OOXML 库（如 Open XML SDK），库负责容器/结构，插件只实现确需的语义映射。

若选择需额外运行时的库，须在首个切片证明目标平台发布包的安装和运行成本；不能
实现完成后要求普通用户临时配置开发环境。不得仅因为易打包改为红字模拟修订。

导出相对准确基准生成真正插入、删除及批注；按 Word 规则处理段落边界、样式与锚点。
新文件再解析、结构校验、渲染和实际客户端的接受/拒绝均承担不同验证职责。

PDF 优先评估 DSH officeToPdf，输出干净稿和标记对照稿有明确用途；转换字体/引擎失败
不静默当成成功。文本/扫描 PDF 的导入是重建路径，保留原件和识别不确定性。

外部返稿按上次导出基准、外部返稿、当前正文比较。优先使用来源标识，再结合文本、
邻近结构和内容关系；重复、拆分或标识消失造成歧义时不自动错贴。

## 9. 已知实现风险

- 编辑器事务到 Word 原生修订的投影，尤其是段落边界、字段、公式和跨段批注。
- 宿主动态 Client 包的依赖身份、主题、翻译、卸载清理及版本漂移。
- 用户部分接受后，跨位置语义依赖和审读结果的适用性。
- 返稿锚点变化与复杂对象完整性，不能用截图相似替代结构证据。
- 辅助运行时、字体及不同 OS 的安装成本，必须在早期发布包切片发现。

风险是早期验证重点，不是取消核心目标或无限扩展框架的理由。
