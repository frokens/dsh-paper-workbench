## Unreleased pending-proposal and sidebar changes

Current source adds `propose.revises` to the existing candidate owner. It names an
exact active pending group and supplies complete replacement operations/translations
against accepted-body selections. A first draft reuses its original empty selection;
it is never accepted just to enable correction, and projected block IDs are not
editable source identities. Earlier candidate content, original status records and
frozen readings remain unchanged. The owner derives a superseded current view from
the new candidate's relation and excludes those predecessors from acceptance,
all-pending projection, turn-triggered reading and returned-change duplication checks.
An exact replay is idempotent; a second replacement or a late old acceptance fails.
Affected incoming dependencies must be included, and remaining pending prerequisites
and linked feedback must be retained explicitly. No separate draft repository,
qualification version or compatibility endpoint is introduced.

The new proposal stores a program-computed `proposalDiff` between the prior projected
combination and the replacement. Its ordinary `diffs` still compare the accepted
source with the proposed operations and govern the eventual decision/export chain.
The two comparison baselines are labeled separately. Proposal/relation/differences
publish in one durable update. A complete revised writing turn uses the same unique
fresh-reader hook; individual proposal calls do not launch readers. Earlier reading
results retain their old combination and cannot certify the replacement.

The Client reuses DSH's exact-version Button, SegmentedTabs and ConnectionIndicator
module and theme tokens. Connection/recovery is distinct from per-comment save
receipts; normal stream completion becomes offline without discarding the document
or dirty comment. Feedback navigation counts saved discussions, while submission
names the unsubmitted comment/reply count. Reading cards show only the findings
located at that block, candidate cards only their associated findings, and findings
without a current source location are grouped once. Full interpretation, original
quotes, evidence and limits remain available. Long reasons and historical proposals
are expandable; the sidebar keeps its own responsive scroll area and native main
conversation/composer stay unchanged.

The Skills distinguish manuscript evidence from surrounding revision bookkeeping,
operation scope from computed differences and translated coverage, submitted feedback
versions from earlier editing history, and proposed state from committed source.
Writing guidance separates design intent, enforced boundaries and observed outcomes,
keeps terms/recipients explicit, and uses the user's language for discussion/review
while preserving manuscript quotations. These are judgment principles, not keyword
tests or a requirement to produce zero findings.

Local checks cover pending bilingual first-draft correction without a body commit,
unchanged paragraphs/translations and old material, both diff baselines, dependency
and feedback preservation, stale/concurrent refusal, durable failure/reopen and one
new turn-level reading. Existing affected lifecycle, reading and comment-recovery
checks pass with type checking and the Host/Client build. Initial fixture failures
from object-prototype comparison and a narrow async-generator type are retained;
the corrected checks compare complete serialized values and body identity.
This is local engineering evidence, not a new installed bundle or model run. The
new external UI module still needs actual DSH loading with the eventual exact new
bundle. Pending-candidate source/translation selection comments are also not yet
supported: the current Feedback targets bind accepted source/translation, so a
pending draft can currently be revised through the native main conversation only.

## Current writing and automatic-reading entry

The current source uses the ordinary main conversation for attachment/path/link
input and new-draft requests. The Host reads references through DSH's bounded file
service and reuses the original import/return/SDK owners. Native alpha1 evidence
below remains evidence for its older manual UI/trigger, not for this new entry.

The existing Open XML SDK creates a real blank DOCX, which enters the same Paper,
immutable baseline, exact selections, candidates, decisions and export path as an
uploaded file. The writing brief is retained as input data from the conversation.
The ordinary main Agent investigates actual material and proposes the draft.
Comment cards autosave; one submission sends the actual saved round to that same
Agent, while main-chat writing requests require no extra sidebar configuration.
There is no separate writing document, model runtime or paper preset.

On the exact empty selection of a single empty paragraph, `fill_draft` proposes
2–100 separate non-empty paragraphs as one pending semantic group. Its real
ProseMirror replacement steps enter the existing acceptance/history owner. The
primary body stays empty until acceptance. Candidate Chinese uses the existing
operation scope, with optional paragraph indexes for one or more paragraphs of
that fill operation; the actual projection and acceptance produce the same source
ranges. Ordinary source selection and concurrency rules remain unchanged. IDs
created by acceptance persist in actual steps and survive replay, undo and body
restoration. Restoring the body does not silently renew Chinese after intervening
source edits: old input remains retained and stale, and explicit new translation
binds the restored body's current ranges. Current paragraph Word export uses the
shared D owner; actual Word limitations are recorded separately.

Four on-demand skills use the existing DSH filesystem provider: research argument
and mechanism, feedback-based local revision, bilingual scientific writing, and
independent reading. Research guidance retains the nine approved judgement layers
and conditional examples; project facts and terms are read from materials.

`reading.ts` owns immutable review material, result validation and applicability.
It consumes the existing candidate acceptance owner's actual projection, full
surrounding body, linked feedback, bilingual projections, writing goal, document
limits and supplied evidence. Relevant submitted human batch directions are
captured verbatim with their batch, revision and feedback scope. A whole-body
reading retains the paper's submitted goal scopes. The author's separately supplied
goal cannot replace them, and later batch changes cannot change the old snapshot.
Directions describe the user's writing goal and scope; author execution steps are
context for the reader, whose task remains reading and located findings.
No parent conversation or hidden author reasoning is copied. Materials are data
for investigation, not executable instructions.

The formal serial `agent/turn-stopping` hook aggregates candidates actually created
by this plugin's native session/turn, including first drafts and chat revisions.
It awaits the existing fresh-child owner with the parent turn cancellation signal.
Actual turn user directions are captured through a disposable asynchronous
`sessionQuery.observeSession` cut, not deprecated synchronous Session log reads.
Same candidates/body revision/baseline projections and the exact captured user
goal reuse the persisted automatic reading, including a stopped or failed outcome.
Same-turn steering that changes that goal starts a replacement reading even when
candidate text is unchanged; the earlier frozen material remains intact. A later
ordinary turn without paper candidates still does not start a reader. No per-propose child or second scheduler
is introduced. Failed projection is a failed Reading with no available child packet.
Startup failure is settled and cleaned before the hook returns. Restart interrupts
unfinished work without silently replaying model calls. Explicit retry reuses the
saved scope and needs no goal/evidence form.

Unrelated turns and owned readers never trigger this process. Translation-only
jobs do not separately launch scientific readers; paired candidate translations
are always frozen and baseline changes retain their existing applicability checks.
The user alone decides acceptance. Published `0.5.0-alpha.2` contains this changed
entry/trigger and reconnect/version/frozen-goal repairs. Its package/public-install
checks and representative automatic DOCX reading now have their own actual evidence;
historical manual-reader evidence is not relabeled as an automatic-trigger check.

The exact owned child can retrieve this same frozen packet through the formal
paper `read` action. The Host resolves its existing `Paper.readings.childId`, not
a live paper binding. It exposes no mutable body or unrelated available-paper
list, and refuses other paper actions in that owned session. The sidebar shows
read-only baseline/proposed material, directions, feedback, evidence and Chinese.
Ordinary linked and unlinked tasks keep their existing paper behavior and general
Agent tools. Snapshot ownership persists across restart without replaying a model
call or creating another document authority. DSH controls whether a child is live;
the plugin does not resume a disposed child through ordinary Session routing.

The shared Host calls DSH's formal `spawn` provider with the exact live parent,
caller delivery and a child-scoped output schema. DSH owns Agent/session creation,
model selection, activation and disposal. The child shares ordinary tools and
preset composition but starts with no inherited conversation. Findings quote
supplied baseline/candidate blocks and identify related candidates, issues,
impact, evidence and suggestions. Completion is not a quality pass or acceptance.

The paper aggregate retains exact source revision, requested/resolved candidate
scope, immutable input, child identity, status and result. Repeating the same request
is idempotent. Explicit retry of a stopped Reading creates a replacement Reading
and fresh child with the saved scope/lineage, retaining the old result; it does not
resume a disposed child. Cancellation addresses the owned activation;
late terminal evidence is retained without publishing a cancelled verdict. Native
caller cancellation and Host teardown release their child. Restart marks unfinished
work interrupted and requires an explicit new request rather than replaying a
chargeable call. Failures and missing/invalid structured capture remain failures.

Applicability distinguishes the original complete candidate combination from the
currently accepted body. Partial acceptance can preserve the original combination's
evidence while leaving the newly accepted combination unreviewed. Source changes
do not erase findings; current locations and historical quotes remain distinct.
Position mapping alone does not establish semantic validity. An explicit recheck
captures its current scope and retains the previous reading and evidence context;
there is no automatic rewrite/review loop or artificial qualification hash.

retry framework. Cleanup warnings are distinct from scientific findings.
