# 反馈执行与审读优化

## 问题与修改

首轮智能体实验中，一次纯中文纠错只产生聊天建议，没有更新实际译文。现有工具已提供
`request_translation` 和 `complete_translation`；写作技能却将纠正描述为用户专用动作。
本次统一工具参数描述、工具指引与两项写作技能，明确使用当前译文的 `mappedSources`
和 `replaces: [{id, version}]` 发起刷新，并核对返回状态。请求记录实际读到的译文版本，
创建任务时在现有存储事务内核对，防止读取后发生的用户纠正被旧请求覆盖；完成时原有
版本核对继续保留。保存的翻译任务结构不变，当前工具参数与消费者同步更新。
待定候选译文仍通过完整后继候选修订，用户
直接纠正译文的界面入口继续保留。正文候选的接受权限不变。

另一问题是固定候选核对者将读者的一般建议升级为补证条件。审读输出的 `impact` 和
`evidence` 描述、独立读者提示及技能现在要求说明候选引入的实际问题、原稿既有问题和
可选建议的区别。明确授权的未来计划与已测量结果分别判断；差异疑问回查完整工具材料，
不以手抄片段重建造成的遗漏指控原稿。侧栏提示用户按证据和影响决定，不把所有发现
视作阻塞。没有新增自动接受、自动互改或隐式放宽事实要求。

这些变更是操作与审读指引的修正，不是新的翻译执行器、语义判定器或模型训练。
工程验证检查已有刷新事务、已完成任务的幂等及冲突拒绝、正文保留和历史审读兼容。
真实模型能否正确选用这些能力须由新实验回答。

## 重新评价

保留首轮全部结果。旧失败任务作为回归材料，不充当未见验证样本。新任务覆盖重复
位置、简单局部修改、多轮候选与用户决定、跨段依赖、双语条件和稿内指令。普通对话
获得相同材料、用户意图、保留约束及轮间事件，可以使用普通工具和持久笔记。

探索任务与确认任务分别标识；运行前固定材料、评分、调用预算、缺失和重试规则。
比较实际候选或保存状态，不把正确建议文字算作写回成功。分别报告任务达成、无关
修改、有害变化阻断、有效修改接受、调用与延迟。结论按任务解释，不把合成任务的
模拟决定当作真人使用效率，也不假定结构化工作台优于普通对话。

## 结果记录中的消息来源

alpha.9 的实验记录审查发现，自动审读目标采集将本轮所有 `user/message` 拼接为用户
方向。DSH 在该事件中同时保存直接用户输入与工程规则、技能目录、运行状态和时间等
注入上下文，正式来源由 `data.source.kind` 区分。alpha.10 的初始过滤仅保留直接用户
输入；独立复审进一步发现批次转发仍标为 `user`，原生目标续写另有 `goal` 来源。
alpha.12 保留直接用户输入与澄清答复，利用同一会话已保存批次的稳定请求身份排除重复模板，
并沿 `goal` 来源的 ID、修订和会话内先前 `goal/change` 冻结实际触发目标。目标版本
缺少记录时明示证据限度，不使用当前可变目标或自动续写模板补造。来源过滤之后再实施
长度上限；按本轮实际进入会话的批次身份，将目标稿件的方向和批注独立冻结，不依赖
写作者提交的反馈关联。同轮切换稿件后，其他稿件的批次模板也不占用直接方向额度。
澄清答复按原生调用身份解析实际选择和自填内容，人工内容先于有界问题上下文进入
采集结果，模型生成的长问题说明不挤掉后续人工约束。
这避免环境文本占用或被误标为本轮用户方向，不修改写作者上下文或宿主规则加载。
工程检查验证多个真实用户消息及答复保留、注入上下文排除、超长批次后的直接方向、
目标版本绑定及缺失证据、未关联批次、换稿和长澄清说明。已结束的模型实验仍对应 alpha.9，alpha.12 的审读语义效果
尚未另作模型比较；原实验材料及结果保持原值。
