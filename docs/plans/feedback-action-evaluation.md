# 反馈执行与审读优化

## 问题与修改

首轮智能体实验中，一次纯中文纠错只产生聊天建议，没有更新实际译文。现有工具已提供
`request_translation` 和 `complete_translation`；写作技能却将纠正描述为用户专用动作。
本次统一工具参数描述、工具指引与两项写作技能，明确使用当前译文的 `mappedSources`
和 `replaces` 发起刷新，并核对返回状态。待定候选译文仍通过完整后继候选修订，用户
直接纠正译文的界面入口继续保留。正文候选的接受权限不变。

另一问题是固定候选核对者将读者的一般建议升级为补证条件。审读输出的 `impact` 和
`evidence` 描述、独立读者提示及技能现在要求说明候选引入的实际问题、原稿既有问题和
可选建议的区别。明确授权的未来计划与已测量结果分别判断；差异疑问回查完整工具材料，
不以手抄片段重建造成的遗漏指控原稿。侧栏提示用户按证据和影响决定，不把所有发现
视作阻塞。没有新增自动接受、自动互改或隐式放宽事实要求。

这些变更是操作与审读指引的修正，不是新的翻译执行器、语义判定器或模型训练。
工程验证检查已有刷新事务、已完成任务的幂等及冲突拒绝、正文保留和历史审读兼容。
真实模型能否正确选用这些能力须由新实验回答。

## 重新评价

保留首轮全部结果。旧失败任务作为回归材料，不充当未见验证样本。新任务覆盖重复
位置、简单局部修改、多轮候选与用户决定、跨段依赖、双语条件和稿内指令。普通对话
获得相同材料、用户意图、保留约束及轮间事件，可以使用普通工具和持久笔记。

探索任务与确认任务分别标识；运行前固定材料、评分、调用预算、缺失和重试规则。
比较实际候选或保存状态，不把正确建议文字算作写回成功。分别报告任务达成、无关
修改、有害变化阻断、有效修改接受、调用与延迟。结论按任务解释，不把合成任务的
模拟决定当作真人使用效率，也不假定结构化工作台优于普通对话。
