# 实施规划

状态：已批准产品设计的实施路线；仓库初始化完成后由专门实施对话执行，主控独立审查。
各批次状态从未开始起，不能因本文存在就标为已实现。当前任务路线保存在本机忽略的
协调文件，PR 中记录本批目标、设计链接、实施/审查对话和必要证据。

## 1. 总目标与完成定义

形成可公开分发、普通用户可在自己的 DSH 安装使用的论文工作台，完整实现从头写作和
上传修订、双语、反馈、局部修改、独立审读、逐处接收、历史与 Word/PDF 交付。

单独网页、mock、构建通过、仅开发环境加载和私有路径安装均不能作为最终完成。
核心产品行为见 reference；实际交付状态由 PR、代码和验收证据确认。

主 Agent 核心架构及原生对话 UI 保持原样。插件是任何普通任务都可打开的侧栏，
不提供“创建论文 Agent”入口、不要求角色/preset/profile 切换或专用会话。这是用户
进一步明确的强制约束，必须从 A 批的注册位置和入口设计开始验证。

## 2. 实施前调查

1. 核当前 DSH 发行版、实际包导出、bundle/Client 构建与安装入口，只读所需源码。
2. 核本机与目标分发平台的编辑器、OOXML、转换引擎、字体和实际 Word 可用性。
3. 画出一个职责复用映射：宿主已有能力、专业库、插件必须新增语义及消费者。
4. 先选最小可安装骨架和 DOCX 修订投影，验证技术路线，再扩大交互和格式范围。
5. 若遇到不能同时满足的条件，立即报告事实、证据、影响和可行选择，不先降低目标。

无需为调查建立独立研究平台、全仓镜像、工作树或多套依赖环境。

## 3. 依赖顺序与职责批次

### A. 可安装原生切片与 Word 文件闭环

目标：在真实 DSH 里打开插件，对一个合成 DOCX 的准确片段提出修改，由用户接收，
下载含可定位批注/修改说明的真实 DOCX，与原稿对照差异。继续复用原生修订和既有重新
导入能力，尽早证明 Host/Client、文档模型和分发路径成立。

交付：一个清楚的 bundle/包、必要构建与锁文件、共享 Host 操作、最小论文标签页、
DOCX 适配与原生修订、合成夹具和相关测试、实测安装说明/技术选择。

必验：实际 bundle 安装、宿主加载与卸载、已有/新建/恢复/非论文任务的统一侧栏入口、
原生对话与主 Agent 不变、无专用 Agent 创建流程、原生工具代表调用、选区与原片段对应、
真实输入/下载 DOCX 的文本、批注锚点、变化、原件保全及可选属性。实际 Word 接受/拒绝
属于保留原证据的扩展检查，不是本轮最小文件闭环的门槛。

排除：大规模模板、实时多人协作、复杂 PDF 恢复、全平台无证据声明。
审查通过后接收本切片，后续批次继续。

### B. 双语、批注和修订生命周期

依赖 A 的文档与宿主接入。

交付：准确修订绑定的翻译、中文两种编辑意图、正文/译文选区反馈、批次提交、真实
增删展示、逐项/成组/全部接收、拒绝与撤销、比较基准、持久化及恢复。

必验：译文迟到、重复选区、拆分/合并、并发人工编辑、部分接收依赖、取消/保存失败、
重启与历史、导师句子保留。先 owner 层检查，再代表性真实 DSH 使用。

功能路径验证后整理侧栏显示与可用性：刷新/保存状态清楚，双语对照与过期提示明确，
批注可定位到实际来源，真实差异、候选组和接受/拒绝层级可理解。保留原生对话与主 Agent，
不以换色或静态截图替代功能验证；最终在 E 批的真实用户流程再次核验。

排除：凭改动更少证明质量、仅整段重写后贴摘要、双语两份独立权威。

### C. 研究写作 Skills 与独立审读

依赖 B 的候选和材料读取。

交付：四类按需技能、从研究材料开始写作、聊天方向与侧栏反馈合并、新会话审读、
具体候选绑定、受影响的复审、明确失败状态和可取消资源。继续保留主 Agent 通用能力。

必验：真实 DSH Agent 调查并正确使用工具，spawn 的独立上下文、审读输出位置和来源、
前后论证/职责/证据/双语问题、候选变化后的结果绑定；核原有通用工具未被插件遮蔽。

排除：父会话自评冒称独立、虚构结果、全局替换 system prompt、无限审改循环。

### D. 文件交付、格式边界及扩展返稿

依赖 A–C。

交付：主对话 DOCX 上传/路径进入同一后台，用户确认所需修改，下载保留原批注并有新增
批注/修改说明的真实 DOCX，提供原稿/下载稿对照样例。继续复用原生修订、干净/双语
DOCX、PDF、三方返稿比较和 Markdown 入口，不为缩小目标新增或删除后台；其他格式按证据声明。

必验：实际输入/导出文件、原批注文本与锚点、真实文本差异、新批注/说明、原件保全和
可选属性；确认工作台内接受不清除交付可见差异，复杂对象按支持域报告。
插件自身 PDF 导出与代表页的文本、双语字体、表图/公式和分页继续独立按原范围验收，
复用未改有效证据并保留默认字体问题；不是本次 Word 样例的新前置或 Word SaveAs PDF 要求。

扩展：桌面 Microsoft Word 自动化、客户端接受/拒绝、SaveAs PDF、命名样式/版面及
复杂导师返稿三方合并/严格往返。过去未验不阻塞最小 Word 文件闭环；已有六件客户端
结果及原失败按原范围保留，不重复 Word 或继续调 AppleScript。

排除：任意格式无损、未实现平台支持、将排版标红冒充 Word 原生修订。

### E. 公开安装、可用性与发布接收

依赖完整路径，安装分发从 A 起持续维护而非本批才开始。

当前交互收敛仍在同一 PR：文档（含导师返稿）只从原生主对话附件/路径/链接进入，
普通 Agent 复用正式文件能力与原导入/返稿 owner，侧栏不留配置表单；Word 式批注自动
保存、一次提交。首稿、主聊天及反馈写作的完整候选在正式轮次完成点自动 fresh 审读，
不逐次 propose 启动，不要求用户配置或手工点审读，不替用户决定。
旧 alpha1 的安装、表单和手工触发实证保持原范围，新交互需准确新候选的原生验收。

交付：已构建公开发布候选、必要 runtime/资源/许可、精确安装/升级/卸载与故障说明、
支持矩阵、独立安装复现、实际 DSH 中的完整用户流程、课程评估材料与准确结论。

必验：使用者不克隆/编译源码、不依赖开发者路径或私人 npm 权限；实际包新安装、
Host/Client/工具/Skills、重启恢复、升级保全、卸载退出；Word 和 PDF 交付；通用 Agent
能力；按实际可用平台验证矩阵。发布包必须对应被验候选，未验处不能写已支持。

完成条件：主控按六向审查和 reference 验收给出功能与架构接收，说明支持域及全部
未决事项；无法完成必验时报告具体阻塞，不自行结束为完整成功。

## 4. 分支、PR 与监督

初始空仓库仅固化用户批准的设计基线。后续各完整职责批次使用短期分支和 Draft PR，
在同一 PR 集中修复。主控独立核 base/head、设计和真实证据，退修原 PR；核准后维护合并。
默认以上五批可对应至多五个主 PR，避免审查对话超限；若有合理拆分，遵守第六个 PR
另开审查对话的规则，不能为凑数合并无关职责。

定期主控工作是审查仓库中新变更/PR 的目标、架构、安装分发和证据，不只报告另一个
任务是否结束。实施任务即时进度由主控当前会话直接跟进。没有新证据不反复回归或
重复通知。用户中途反馈保持原目标，范围变化明确记录。

## 5. 测试、预算及重新打开

快速检查在昂贵真实执行前；按影响选最小充分测试。预计超过增量预算先说明独有风险
和预计耗时，不拆组规避累计。代码/输入/依赖未变的适用证据可复用，不伪称新全量通过。

批次出口固定交付、必验、排除和结束条件。新实现、失败、关键消费者变化或新证据
否定先前假设时才重新打开受影响范围；措辞修改不触发无关模型重验。新增产品要求
和超范围治理由用户裁决，不能由中途建议偷偷扩充。
