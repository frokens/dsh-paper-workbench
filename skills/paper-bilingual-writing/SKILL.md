---
name: paper-bilingual-writing
description: Translate or revise a linked paper while preserving the accepted primary-language wording and explicit bilingual intent.
---

Read `paper_workbench` for the current source, primaryLanguage, translationLanguage, requested translation jobs, feedback and exact selections. English is the default primary with Chinese projections; an explicitly chosen Chinese primary projects English. Use the Paper's language choice rather than the conversation or interface language. Translation is revision-bound, not a second editable primary paper. Preserve negation, quantities, conditions, claim strength, definitions, citations and the distinction between decision and execution.

Use the user's conversation language for explanations and discussion; manuscript and projection languages remain the Paper's explicit choice. Use consistent terminology for the same concept in both languages, and different terms for genuinely distinct concepts. Do not turn a design intention into a measured effect or an implementation boundary into a claim about readers' behavior.

Use document references from the native main conversation. Import the readable DSH path of an attachment/@file/explicit path, or first investigate/download a link with the ordinary tools. Preserve a stable import request identity and never pass document base64 through the model. Import prepares paragraph translation jobs; complete those jobs in the same ordinary turn so both languages appear without asking the user to prepare or Send a second request. Ambiguous input/mentor baselines and unresolved Word-revision choices are clarified in the main conversation.

For an explicit pending translation job, use `complete_translation` with sourceIndexes into that job and aligned groups. Groups may cover multiple source selections; do not infer a character-by-character alignment. A completed job can only acknowledge the identical original result. Do not publish a cancelled, superseded or stale result or request a replacement job to bypass a failed receipt without checking durable state.

Distinguish two user intents. Correcting translation wording changes only the projection through the human correction action; it must not back-translate or overwrite confirmed primary text. Changing research content through translation feedback creates precise primary-body candidates and corresponding candidate translations in translationLanguage with operationIndexes. Explain necessary conceptual linkage; preserve other confirmed sentences. Do not invent evidence to make the two languages appear consistent.

The selected operations' resulting source ranges define candidate translation coverage exactly. Choose a scope covering everything translated; the program does not widen it from translation text. Unchanged portions of a replace are preserved by the computed diff, so a wider source scope for a sentence translation does not require unrelated textual changes.

For a multi-paragraph first draft, one `fill_draft` operation supplies separate actual paragraphs on the exact empty selection. Candidate translations use `operationIndexes: [0]`; optional zero-based `paragraphIndexes` binds one or more of that operation's paragraphs. Omit paragraphIndexes to cover all its paragraphs. Do not assign every translated paragraph to the entire draft when it describes only one source paragraph. These remain pending projections and enter the accepted source's real ranges only when the user accepts.

When revising a pending bilingual proposal, name its exact current candidate group with `propose.revises` and supply the complete corrected operations and paired translations against accepted-source selections. Preserve unaffected source and translation text. For a pending first draft, reuse the original empty selection, not projected block IDs. Earlier candidate translations and readings keep their original scope; the revised group is reviewed afresh at the completed writing turn.

Pending translation comments name `candidate_translation` and an exact translation index/range, while `candidate_source` comments name an operation/result paragraph. These refer to proposed content and must not be used as accepted-source operation selections. A wording correction to a pending translation belongs in the complete revised candidate, retaining its primary text; the human translation-correction action applies to an already accepted translation ID/version. Read the original candidate referenced by submitted feedback even after it becomes historical, and keep its quote distinct from the current replacement.

For example, with an English primary, a request to improve the Chinese rendering of “not yet verified” leaves the English condition intact. A request to clarify what has been verified must first resolve the actual evidence and propose both the source change and its Chinese counterpart; it cannot silently turn an unverified result into a validated one. The same separation applies when Chinese is primary and English is the projection.

The program maps unchanged source selections and marks affected projections stale. Read a changed or conflicted source again. When this writing turn's candidate combination is complete, the Host automatically starts a new independent reader covering both languages; do not start a duplicate child. Translation-only jobs do not separately launch scientific reviews. A completed translation or a bilingual-looking screen does not prove scientific correctness; retain actual findings and evidence limits, and leave all candidate decisions to the user.
